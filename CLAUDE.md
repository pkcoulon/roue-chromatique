# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Langue

Tout le dépôt est en français : identifiants JS, commentaires, textes d'interface, messages de commit (sujet impératif court, ex. « Colonne de gauche redimensionnable horizontalement »). Continuer en français.

## Deux artefacts indépendants

- **`index.html`** — **Chromathèque**, l'application web complète dans un seul fichier (CSS + HTML + JS inline, ~3900 lignes). Aucun framework, aucun build, aucun npm. Déployée par GitHub Pages : un push sur `main` publie sur https://vgonnot.fr (fichier `CNAME`). (`roue_lab.py` et `README.txt` portent encore l'ancien nom « Roue chromatique » : ils décrivent l'artefact bureau, renommés séparément le jour où ce sera demandé.)
- **`roue_lab.py`** — version bureau autonome (numpy + matplotlib) qui génère 2 PNG (roue et plan L/C) et ouvre 2 fenêtres. Documentée dans `README.txt`, réglages en tête de fichier (`L_FOND`, `CHROMA_MAX`, `POINTS`…). Lancement : `pip install -r requirements.txt && python roue_lab.py`.

Les deux implémentent le même moteur colorimétrique (Lab ↔ sRGB en D65, limites de MacAdam recalculées depuis les CMF CIE 1931 + SPD D65) — une correction dans l'un se reporte souvent dans l'autre.

## Développement local (web)

```bash
python3 -m http.server 8642        # puis http://127.0.0.1:8642/index.html
```

Pas de tests ni de linter. La porte de connexion Firebase (`#porte`) bloque toute l'interface ; pour tester sans compte, dans la console : `document.getElementById('porte').hidden = true` (les fonctions Bibliothèque/Compte resteront inertes, tout le reste marche en local).

## Architecture de `index.html`

- **La palette est la source unique des colorants.** Chaque point porte un identifiant stable (`id`, posé par `normaliserPoint`) ; l'analyse spectrale, la carte d'identité et les mélanges n'en gardent qu'une **référence**, jamais une copie du nom ni des coordonnées. Renommer une couleur se propage donc partout sans migration, et `synchroniserColorants()` — appelé par `majTout` — écarte les références devenues mortes. Ne jamais réintroduire de liste de colorants parallèle : un nom de colorant ne doit exister qu'une fois, dans `points`.
- **Tout point créé passe par `normaliserPoint`** — c'est lui qui pose l'`id`. Un `points.push({…})` direct crée un point sans identifiant : les analyses, les mélanges et la ligne ouverte s'y rattachent par `id`, et tout ce qui en dépend échoue en silence (`choisirColorantActif` sort sans rien faire, `pointParId` ne trouve rien).
- **`majTout(true)` refait les panneaux Analyse spectrale et Carte d'identité**, `majTout(false)` non — le chemin rapide tourne à chaque image d'un glisser. Oublier ce rafraîchissement laissait « Aucun colorant » affiché après qu'une palette ait été remplie depuis une autre vue.
- **Sélecteur de colorant** : `creerComboColorant(hote, {valeur, surChoix})` construit un combobox filtrant (un `<select>` natif ne se cherche pas). Recherche insensible à la casse et aux accents (`sansAccents`), message explicite quand rien ne correspond ou que la palette est vide. Les instances s'inscrivent dans `combos` et `rafraichirCombos()` élague au passage celles dont l'hôte a quitté le DOM — sans quoi les combos reconstruits avec leur panneau s'accumuleraient. **La liste est en `position: fixed`, placée en JS** : la colonne défile (`overflow:auto`) et le contenu d'un `<details>` est en `overflow: clip` pendant l'animation de dépliage — en `absolute` elle était coupée par les deux. D'où aussi la fermeture au défilement, par un écouteur global unique (un par instance s'accumulerait).
- **Système de design** : un bloc de jetons en tête de feuille (`--f-*` familles, `--t-*` échelle typographique, `--e-*` espacement au pas de 4, `--r-*` rayons, `--h-ctl`/`--h-tete`/`--aside-w` gabarit, puis les couleurs). Les huit variables historiques (`--bg --card --ink --muted --hairline --accent --input-bg --canvas-ground`) sont conservées. **Écrire une valeur en dur dans une règle est une régression** : tout passe par un jeton. Le thème sombre est dupliqué en deux blocs (`@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` et `:root[data-theme="dark"]`) — CSS n'a pas de mixin, la duplication est voulue. Trois états de thème : système (aucun attribut), clair, sombre, cyclés par `#btn-theme` et mémorisés dans `rouelab.theme`. `@media (pointer: coarse)` porte `--h-ctl` à 40 px : c'est le seul endroit qui règle les cibles tactiles.
- **Châssis** : `body { overflow: hidden }` et `.chassis` en `grid-template-rows: var(--h-tete) 1fr`. **La page ne défile plus** : `aside` et `main` sont deux régions à défilement propre (`overflow-y:auto; overscroll-behavior:contain`). Une palette dépliée n'entraîne donc plus les planches hors de l'écran. Sous 1180 px, `aside` passe en tiroir (`position:fixed` + `[data-ouvert]`), ouvert par `#btn-tiroir` et refermé par Échap, par un changement de vue ou par le premier geste sur `main`.
- **Vues** : les trois onglets `[data-choix-vue]` de l'en-tête basculent entre « roue », « spectre » et « identite » en masquant tout élément dont l'attribut `data-vue` ne contient pas `vueCourante` (`appliquerVue`). C'est une **navigation** : elle vit dans l'en-tête, pas dans la colonne. `data-vue` accepte **plusieurs vues séparées par une espace** (`data-vue="spectre identite"`). Les éléments sans `data-vue` restent visibles. Vue mémorisée dans `localStorage`, validée contre `VUES` au chargement.
- **Surfaces flottantes** : Bibliothèque, Réglages et Compte ne dépendent d'aucune vue — ils vivent dans des `.flottant` ouverts par les boutons `[data-surface]` de l'en-tête, fermés par `[data-fermer]`, par le fond ou par Échap. Ne pas les remettre dans la colonne : c'est ce qui donnait sept accordéons au même niveau. `#bloc-compte` est le **bouton** d'en-tête (masqué hors connexion par `initCompte`), pas le panneau.
- **Canvas** : trois canvas (`cv-roue`, `cv-lc`, `cv-spectre`), toujours en thème sombre (constantes `G`), redessinés via `redessiner()`/`majTout()` + un `ResizeObserver` sur `.zone-canvas`. Chaque dessinateur commence par `if (!cv.clientWidth) return;` — un canvas de la vue masquée a une taille nulle et `ctx.arc` à rayon négatif lève une exception qui casse tout le rafraîchissement. Utilitaires partagés : `prepCanvas` (DPR), `pilule` (étiquettes). (Le solide sRGB 3D a été retiré ; ne pas le réintroduire sans demande.)
- **La planche de mesure** : `.zone-canvas` reste à `--canvas-ground` (#101014) dans les deux thèmes — une couleur ne se juge pas sur un fond qui change. En thème clair elle est enveloppée d'un `.plan` (passe-partout `--plan-mont` + bord `--plan-bord`) : le cadre est assumé, pas subi. En vue Roue, `.grille-roue` est en `1fr auto` et les planches prennent la hauteur restante ; sous 1180 px elles repassent à leur ratio, bornées à `62vh`.
- **Ligne de colorant** : la palette est une liste de lignes de 34 px en lecture (pastille, nom, L/a/b en monospace tabulaire, une colonne chacun) et **un seul colorant est ouvert à la fois** — `pointOuvert` porte son `id`, `ligneFermee`/`ligneOuverte` produisent les deux formes. `.pt.ouvert` change de `display` mais n'est jamais masqué, donc reste compatible avec `[hidden]`. Le chemin rapide de `majTout(false)` doit rester tolérant : les sélecteurs `.pt-hex`, `.epingle` et `input[type=number]` n'existent que sur la ligne ouverte.
- **Hiérarchie des boutons** : `primaire` (une seule action par panneau), secondaire (défaut, sans classe), `discret` (outils d'en-tête de carte), `suppr` (croix au repos, plein une fois armée par `armerSuppr`) et `danger`/`danger-plein`. Ajouter un deuxième bouton primaire dans un panneau est une régression.
- **Mélange de colorants** (vue roue) : modèle soustractif **Kubelka-Munk à constante unique** sur les trois canaux sRGB linéaires — `K/S = (1−R)²/2R` est additif en concentration, ce qui donne le vrai comportement des colorants (bleu + jaune → vert) là où une interpolation dans Lab donnerait un gris. Deux degrés de liberté : les proportions (simplexe échantillonné par `grilleSimplexe`, pas choisi par `pasSimplexe` pour rester sous ~600 combinaisons) et la profondeur de nuance (`PROFONDEURS`, 0,1× à 8× la concentration de référence). `voileGamme` trace l'union des courbes de profondeur dans un canvas hors écran et s'en sert comme masque pour assombrir les teintes inatteignables. `resoudreMelange` fait le chemin inverse (balayage grossier puis descente locale sur ΔE\*ab) pour produire la formule. **Les proportions restent dans la colonne, le résultat pesé va dans `#carte-resultat`** (contenu principal, sous le plan luminosité/chroma) : c'est ce qui comble le vide de cette moitié d'écran. `rendreFormule` produit un état vide (`etatVide`) quand il manque des colorants ou une cible.
- **Carte d'identité** (vue identite) : partage le registre `spectres.colorants` avec l'analyse spectrale — un colorant porte `identite` (fournisseur, CI, lot, réception ; la « Référence du colorant » est le lien vers la palette, pas un texte libre), ses essais et ses spectres. Les catégories d'essais viennent d'une source unique, `TYPES_ESSAIS` (`lumiere`, `pvc`, `ccm`), que le normaliseur parcourt ; `ONGLETS` décrit ce que chacune affiche (libellé, champ notation, outil de mesure). **Ajouter une catégorie exige les deux** — l'oublier dans `TYPES_ESSAIS` laisse `essais.<type>` indéfini et casse le rendu. L'onglet CCM ajoute un outil de cotation : deux segments h et H tracés sur la photo, mémorisés en pixels de l'image d'origine (donc justes quel que soit le zoom), avec calcul automatique de h/H dès que les deux existent. Ils sont dessinés en cotes décalées de part et d'autre, faute de quoi h — qui part du même dépôt que H — disparaîtrait dessous. Remplacer ou retirer la photo remet les segments à zéro. Les photos sont réduites et ré-encodées en JPEG par `photoDepuisFichier` (canvas) avant stockage ; `sauverSpectres()` renvoie `false` si le quota localStorage est atteint, et l'appelant restaure la valeur précédente plutôt que de perdre les données en silence. Les champs texte n'entraînent pas de re-rendu à la frappe (le curseur serait perdu).
- **Boutons génériques** : `data-png` (export PNG) et `data-plein` (quasi plein écran, sortie par Échap) sont câblés une fois au chargement par `querySelectorAll` — un bouton ajouté dans le HTML statique est pris en charge automatiquement.
- **L'étude est l'unité de la Bibliothèque.** Une étude = la palette **et** les colorants qui la référencent (identité, essais, photos, spectres) **et** le mélange. Enregistrer une palette seule laisserait ses analyses derrière : elles ne gardent qu'un `id` de point. `etudeCourante()` capture l'état, `appliquerEtude()` le remplace en entier (d'où le chargement armé en deux clics), `normaliserEtude()` écarte toute référence morte — colorant ou constituant de mélange dont le point a quitté la palette.
- **Une étude = un document Firestore.** Le document racine `bibliotheques/{uid}` ne porte que l'**index** (`dossiers[].etudes[]` : id, nom, date, aperçu de 5 couleurs, résumé chiffré) ; chaque étude vit dans `bibliotheques/{uid}/etudes/{id}`. **C'est la seule façon d'y mettre les photos d'essai** : un document Firestore est plafonné à 1 Mio et une photo pèse 100 à 200 Ko — tout dans un document unique saturait après deux ou trois études. `ecrireEtudeCloud` refuse au-delà de `MAX_ETUDE` (900 Ko) plutôt que de laisser le serveur rejeter avec un message obscur, et l'index n'est complété **qu'après** l'écriture réussie : jamais d'entrée pointant vers un document inexistant.
- **Compatibilité** : les entrées d'avant portaient la palette en clair dans l'index, sans `id` ni document séparé (`normaliserEntree` les lit toujours ; `chargerEtude` sert `ent.points` sans aller au réseau). Elles deviennent des études complètes au premier réenregistrement. L'export JSON est en `version: 2` (dossiers d'études complètes, photos comprises) et l'import accepte les deux formats.
- **Le travail en cours remonte tout seul sur le compte**, pas seulement ce qu'on enregistre : `planifierPousseCourant()` (debounce 3 s, écriture sautée si la charge est identique à la précédente) écrit l'état dans le document réservé `bibliotheques/{uid}/etudes/courant`. Il n'est pas dans l'index, donc il n'apparaît jamais dans la liste des études — c'est un brouillon.
- **La réconciliation est une fonction pure, `deciderSync()`** — isolée du réseau précisément pour être vérifiable seule (neuf cas de bascule entre postes). Trois issues : `adopter` (le compte est plus récent), `pousser` (le local est plus récent), `vider` (l'état local appartient à un autre compte et il n'y a rien à reprendre). Deux règles portent tout :
  - **`rouelab.uid` marque à quel compte appartient l'état local.** Sans lui, deux comptes sur le même navigateur se déversent l'un dans l'autre : A travaille, se déconnecte, B se connecte, et le travail de A — plus récent — remonte dans le compte de B. L'état local d'un autre compte ne remonte **jamais** ici.
  - Sinon la version la plus récente gagne (les dates ISO s'ordonnent comme des chaînes).
- **L'écriture du brouillon est conditionnelle** (`ecrireCourant`, dans une transaction Firestore) : si le document porte un `maj` que ce poste n'a pas vu, c'est qu'un autre poste a écrit entre-temps, et on **refuse d'écraser en silence**. L'état de synchronisation le dit et un bouton « Écraser avec ce poste » laisse l'utilisateur trancher ; recharger prend l'autre branche. `majConnue` est posé à chaque lecture **et** à chaque écriture — l'oublier après `reprendreCourant` ferait croire à un conflit dès la première écriture.
- **Le garde `pretPourSync` n'est pas optionnel.** L'initialisation appelle `sauverPoints`/`sauverMelange`/`sauverSpectres` ; sans ce drapeau (posé à `true` seulement à la fin du script), un navigateur vierge daterait son état vide de « maintenant » et **l'écraserait sur le travail du compte** à la première connexion. Toute nouvelle sauvegarde appelée pendant l'initialisation doit rester derrière ce garde.
- **Les photos d'essai sont des documents à part**, voisins des études dans la même collection `etudes` — donc couvertes par la règle déjà publiée, sans rien à changer côté serveur. Elles sont **adressées par leur contenu** (empreinte SHA-256 tronquée, `detacherPhotos` / `rattacherPhotos`) : la même photo n'est jamais écrite deux fois et réenregistrer une étude n'en réécrit aucune. Conséquence assumée : **une photo n'est jamais supprimée** — plusieurs études peuvent référencer la même. Le document d'étude ne garde qu'un `photoRef` ; l'état local, lui, porte toujours la photo en clair (`photo`), jamais de `photoRef`. Une photo introuvable laisse son essai sans image plutôt que de faire échouer tout le chargement.
- **Le compte recense tout, le navigateur n'en est qu'un miroir.** `oublierTravailLocal()` efface les `CLES_TRAVAIL` à la déconnexion — sur un poste partagé, les fiches et les photos d'un compte n'ont rien à faire là une fois la session close. Les préférences d'affichage (`vue`, `theme`, `asideW`) survivent : elles n'appartiennent à personne. **Le garde `avant` n'est pas optionnel** : `onAuthStateChanged` tire aussi avec `null` au premier chargement sans session, et sans lui ouvrir l'application hors compte effacerait le travail.
- **Quotas** : deux plafonds distincts, aucun théorique dès qu'il y a des photos — le stockage du navigateur (`PLAFOND_LOCAL`, ~5 Mo, mesuré sur `CLES_LOCALES`) et le document d'étude Firestore (1 Mio, `MAX_ETUDE` = 900 Ko de marge, **photos exclues** puisqu'elles sont stockées à part). `majQuotas()` alimente deux jauges dans les Réglages ; `etatSync()` y écrit l'état de synchronisation. Le seuil d'alerte des jauges est à 80 %.
- **État et persistance** : palette → `rouelab.points.v1`, colorants (spectres + identité + essais) → `rouelab.spectres.v1`, mélange → `rouelab.melange.v1`, horodatage de la dernière modification → `rouelab.maj`, vue → `rouelab.vue`, thème → `rouelab.theme`, largeur de colonne → `rouelab.asideW` (localStorage). L'index de la Bibliothèque vit uniquement sur le compte Firestore, poussé avec un debounce (`planifierPousseCloud`) ; les études sont écrites à l'unité, sans debounce.
- **Firebase** : SDK compat chargé depuis jsdelivr avec empreintes SRI. Création de comptes désactivée côté serveur (comptes créés à la main dans la console Firebase). La config `FIREBASE_CONFIG` est publique par conception. **Les règles Firestore doivent couvrir la sous-collection `etudes`** — une règle sur le seul document `bibliotheques/{uid}` ne s'y étend pas :

  ```
  match /bibliotheques/{uid} {
    allow read, write: if request.auth.uid == uid;
    match /etudes/{etude} {
      allow read, write: if request.auth.uid == uid;
    }
  }
  ```
- **Import Excel** : SheetJS chargé à la demande une seule fois (`chargerXLSX`, SRI). Deux parseurs : `pointsDepuisFeuille` (palette L/a/b) et `spectreDepuisFeuille` (spectre λ/A). Les deux détectent la ligne d'en-tête et acceptent la virgule décimale française.

## Conventions de sécurité (à respecter pour tout nouveau code)

- Toute donnée d'origine non fiable (localStorage, JSON importé, Firestore, Excel, photos) passe par une fonction `normaliser*` (`normaliserPoint`, `normaliserDossiers`, `normaliserMesure`, `normaliserColorants`, `normaliserMelange`, `normaliserIdentite`, `normaliserEssai`) : nombres bornés, chaînes forcées et tronquées (`texteBorne`), dates vérifiées au calendrier (`dateBornee`), photos acceptées seulement sous la forme exacte que produit l'application (`normaliserPhoto` : data URL image ré-encodée, ce qui écarte `javascript:` et `data:text/html`). Ajouter une source de données = ajouter/réutiliser un normaliseur.
- Ne jamais interpoler une chaîne non fiable dans du `innerHTML` : construire avec `textContent`, `.value`, `new Option(...)` (correctif XSS de `175e212`).
- La CSP (balise `<meta>`) n'autorise que les scripts self + jsdelivr et les connexions googleapis. Un nouveau script CDN exige son empreinte SRI et, si besoin, une mise à jour de la CSP.

## Pièges CSS connus

- Règle globale `[hidden] { display: none !important; }` : nécessaire car toute règle d'affichage (`display:flex` sur `.actions`…) écraserait sinon l'attribut `hidden`. **Ne jamais poser `display` sur un élément porteur de `data-vue`** par une autre règle.
- Thème clair/sombre par variables CSS (`prefers-color-scheme` + surcharge `data-theme`) pour l'interface ; les surfaces canvas restent sombres quel que soit le thème.
- `.note:empty { display: none }` : plusieurs `.note` ne servent qu'à recevoir un message transitoire (import, quota, connexion) et ne doivent pas laisser de trou quand elles sont vides.
- Suppressions en deux clics via `armerSuppr` (pas de `confirm()` bloquant).
- **Le commentaire `/* … */` ne supporte pas `L*/C*`** : la séquence `*/` ferme le bloc et casse tout le script. Écrire « luminosité / chroma » en toutes lettres dans les commentaires JS.
